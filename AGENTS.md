# AGENTS.md

Windows-only tray app (C# / .NET 8 WinForms) showing Bluetooth device battery levels. One project: `src/BtBatteryTray`. No tests, no CI.

## Communication & workflow
- The user writes in French: answer in French, keep code comments, README, PLAN, commit messages and UI strings in French.
- The user installs software themselves: give `winget` commands, don't install tools.
- `PLAN.md` is the project log (design table, steps, session journal): update it when behavior or design changes.
- Commit and push to `main` (`origin` = github.com/BechirZalila/bt_speaker). Releases are made with `gh` and ship the Inno Setup installer only (not the bare exe).

## Commands
- Build: `dotnet build src/BtBatteryTray`. Output goes to `bin/Debug/net8.0-windows10.0.19041.0/` (TFM includes the Windows SDK version).
- Quick check without UI: `BtBatteryTray.exe --list [--verbose]` (prints levels to the parent console through `AttachConsole`).
- Diagnose events: `BtBatteryTray.exe --log` → `%TEMP%\BtBatteryTray.log`.
- Stop the running instance before rebuilding (`Get-Process BtBatteryTray | Stop-Process`): the exe is locked, and a single-instance mutex `Local\BtBatteryTray` makes a second launch exit silently.
- Installer: `.\tools\build-installer.ps1` → `artifacts\BtBatteryTray-Setup-<version>.exe` (needs Inno Setup 6; version is read from `<Version>` in the csproj).
- Release publish settings (single-file, framework-dependent, win-x64) live in the csproj under `Configuration == Release`.
- `install.ps1` / `uninstall.ps1` are dev-only installs into `%LOCALAPPDATA%\BtBatteryTray`. The setup installs to `%LOCALAPPDATA%\Programs\BT Battery Tray`. Don't mix the two.

## Architecture / gotchas
- Battery level = PnP property `{104EA319-6EE2-4701-BD47-8DDBF425BBE5} 2` (byte), read through cfgmgr32 (`BatteryReader.cs`). It sits on a *service* node (e.g. `P9 Hands-Free AG`): the display name and the connected state come from the physical `BTHENUM\DEV_…` / `BTHLE\DEV_…` node with the same `ContainerId`.
- Connected state = undocumented key `{83DA6326-97A6-4088-9453-A1923F573B29} 15` (bool). Nodes stay "present" and keep a stale battery value when the device is off.
- Change notifications use the WinRT `DeviceWatcher` (`DeviceWatcher.cs`). The native `DevCreateObjectQuery` returns `0x8007007E` on this machine (build 26300): don't switch back to it.
- AQS filters reject `{GUID} pid` keys and `System.Devices.EnumeratorName`. Only canonical names like `System.Devices.DeviceInstanceId:~<"BTHENUM\"` work. Raw keys are fine in the `additionalProperties` list.
- Tray icon digits are drawn as a scaled `GraphicsPath` (`BatteryIcon.cs`): `DrawString` truncated the second digit.
- Run-at-startup = HKCU `...\CurrentVersion\Run` value `BtBatteryTray`, written by both the app menu and the installer. The menu shows it as checked only if the path matches `Environment.ProcessPath`.
- Settings: `%APPDATA%\BtBatteryTray\settings.json`.
- `src/BtBatteryTray/app.ico` is generated by `tools/make-icon.ps1`. Regenerate it, don't hand-edit it.
- `.ps1` and `.iss` files containing accented text must be saved as UTF-8 **with BOM** (otherwise mojibake in Windows PowerShell 5.1 and Inno Setup).
- Keep the `AppId` GUID in `installer/BtBatteryTray.iss` unchanged (it drives upgrades and uninstall). `UpdateChecker.cs` also uses it to find the `..._is1` uninstall key.
- In-app updates (`UpdateChecker.cs`) depend on the release format: tag `vX.Y.Z` (compared with `<Version>`), marked "Latest" (not draft or prerelease), with an asset named `BtBatteryTray-Setup-*.exe`. Bump `<Version>` before building the installer for a release, or installed apps will keep offering the update.
- The installer is started with `/SILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE=1`. `IsAppUpdate` in the `.iss` reads `/UPDATE=1`: it leaves the Run key untouched and relaunches the app. Keep both sides in sync.
- Test the updater without installing: `BtBatteryTray.exe --check-update [--download]`. To simulate an older version: `dotnet build src/BtBatteryTray -p:Version=0.9.0 -o <dir>`.
